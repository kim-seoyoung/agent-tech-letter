DEEP DIVE 01

Claude Sonnet 5: 에이전트를 겨냥한 프런티어 라인의 더 싼 미들 티어

blog_post

Anthropic이 6월 30일 Claude Sonnet 5를 공개했어요(anthropic.com). 도입 가격은 100만 토큰당 입력 2달러·출력 10달러예요. 8월 31일까지 이 가격이 유지되고, 이후에는 3달러·15달러로 올라가요. Sonnet 4.6의 3달러·15달러와 견주면 도입기 단가만 놓고 봤을 때 그 절반이 안 되는 수준이에요. 무료·Pro 플랜의 기본 모델로도 편입됐고, Max·Team·Enterprise에서도 골라 쓸 수 있어요.

벤치마크는 세 축에서 움직였어요. 에이전트 코딩 지표인 SWE-bench Pro는 63.2%예요. 직전 세대인 Sonnet 4.6이 58.1%였고, 최상위인 Opus 4.8이 69.2%예요. 컴퓨터 사용 능력을 재는 OSWorld-Verified는 81.2%로 4.6의 78.5%보다 2.7%포인트 위예요. 일반 사무 지식을 재는 GDPval-AA v2는 1,618점이에요. Opus 4.8은 1,615점이라 사실상 동률이에요. 정리하면 코딩 정확도는 여전히 Opus 4.8이 위지만, 오피스형 지식 태스크에서는 Sonnet 5가 상위 티어와 어깨를 맞춰요.

TechCrunch는 이 릴리스를 "에이전트를 더 싸게 굴리기 위한 미들 티어"로 요약했어요(techcrunch.com). Anthropic도 다단계 계획·브라우저 조작·터미널 조작 같은 동작을 이전엔 Opus 급 연산이 필요했던 폭까지 처리한다고 적었어요. 다만 한 가지 유의점이 있어요. 이번 릴리스에서 토크나이저가 갱신되어, 같은 입력이 대략 1.0~1.35배의 토큰으로 매핑돼요. MarkTechPost는 콘텐츠 유형에 따라 입력이 최대 35%까지 부풀 수 있다고 인용했어요. 겉으로 보이는 단가는 4.6의 절반 이하지만, 콘텐츠에 따라 체감 비용은 이 배수만큼 상쇄돼요.

선행 흐름과 견주면 두 지점이 눈에 들어와요. 지난주 다룬 Sakana Fugu·GPT-5.6 Sol의 ultra 모드가 "여러 모델을 학습된 정책으로 묶는 방향"이었어요. 이번 Sonnet 5는 반대로 "단일 프런티어 티어를 값싸게 낮춰 파는 방향"이에요. 다른 하나는 미들 티어가 상위 티어와 어깨를 맞추는 지표가 나오기 시작했다는 점이에요. 자기 팀 스택이 지금 Sonnet 4.6이나 Opus 4.8 위에서 도는 팀이라면, 프로덕션 트래픽의 최근 24시간치 프롬프트를 Sonnet 5의 새 토크나이저로 다시 세어보고 같은 태스크에서 총 토큰 비용이 정말 내려가는지부터 확인해보세요.

DEEP DIVE 02

Claude Science: 새 모델 없이 스킬·커넥터를 얹어 과학자를 겨냥한 워크벤치

blog_post beta

Anthropic이 같은 6월 30일 Claude Science를 베타로 함께 공개했어요(anthropic.com). Pro·Max·Team·Enterprise 플랜 사용자에게 열려 있어요. 회사가 첫 문장에서 강조한 지점은 "새 모델도 아니고, 생물학용으로 확장된 모델도 아니다"라는 부분이에요. 안에서 도는 모델은 이미 공개된 Claude Opus 4.8이에요. 별도 접근 게이트도 걸려 있지 않아요.

핵심은 워크벤치 앱 자체예요. 여러 도구와 데이터 커넥터를 미리 붙여 두고 감사 가능한 실행 기록을 남기는 얼개예요. 큐레이션된 스킬·커넥터가 60개 넘게 얹혀 있어요. 60개 이상의 과학 데이터베이스도 미리 등록돼 있어요. 분야는 genomics·single-cell·proteomics·structural biology·cheminformatics 같은 축을 두루 덮어요. 사용자는 한 명의 코디네이터 에이전트를 상대로 대화하고, 그 에이전트가 세부 스킬을 골라 굴려요. 결과 아티팩트로는 3D 단백질 구조와 genome browser 트랙까지 앱 안에서 렌더링해 준다고 적혀 있어요.

TechCrunch는 이 접근을 "새 모델이 아니라 워크플로에 베팅"으로 요약했어요(techcrunch.com). 같은 날 NVIDIA도 자사 BioNeMo Agent Toolkit이 Claude Science 안의 스킬로 실려 있다고 공개했어요(blogs.nvidia.com). 즉 "새 모델은 없지만 도메인 툴킷·데이터·감사 로그는 미리 얹혀 나온다"라는 그림이에요. Anthropic은 여기에 자금 신호까지 붙였어요. "AI for Science" 프로젝트를 최대 50건 뽑아 각 3만 달러 상당의 크레딧을 지원한다고 했어요. 신청은 7월 15일까지, 통보는 7월 31일까지예요.

이 흐름의 인접 사례는 3주 전 다룬 Stack Overflow for Agents나 지난달의 Databricks LTAP처럼 "모델 위에 지식·컨텍스트 계층을 얹어 파는" 방향이에요. 다만 Claude Science는 스코프가 생명과학·화학 도메인으로 좁혀져 있어요. 도메인 스킬을 자체 조립해 온 팀에게는 한 가지 검증 지점이 생겨요. 자기 파이프라인에서 자주 도는 도메인 태스크 하나를 Claude Science의 코디네이터 에이전트에 그대로 붙여보고, 감사 로그에서 어떤 스킬·데이터 소스를 실제로 호출했는지부터 대조해보세요. 얼마나 겹치는지가 마이그레이션 계산의 첫 수치가 돼요.

DEEP DIVE 03

OpenViking: 메모리·RAG·스킬을 파일시스템 하나로 묶은 자기진화 컨텍스트 DB

repo beta

Volcengine이 6월 말 OpenViking을 오픈소스로 풀었어요(github.com). 별 2만 6천여 개, 포크 2천여 개 규모예요. 라이선스는 본체가 AGPLv3이에요. CLI와 예제만 Apache 2.0이라 상용 워크로드에 얹으려면 라이선스부터 짚어야 해요. 언어 구성은 Python 75%, Rust 14%, TypeScript 6%예요. 태그라인은 짧아요. "Self-evolving Context Database for AI Agents. Unify Agent Memory, Knowledge RAG and Skills."

핵심 아이디어는 세 가지를 한 저장소로 통합한 지점이에요. 사용자 선호·실행 경험을 담는 에이전트 메모리, 계층 구조 위의 RAG, 그리고 도구·스킬 통합을 한 계층으로 얹었어요. 접근 인터페이스도 벡터 스토어의 평평한 검색이 아니에요. viking:// URI로 자원을 지정하는 파일시스템 은유를 씁니다. 컨텍스트는 세 단계로 계층 로드해요. L0는 요약, L1은 개요, L2는 세부예요. 상단 요약만으로 결정할 수 있는 상황에서는 전체 문서를 읽을 필요가 없어요. 결과적으로 토큰이 줄어들어요.

설치는 pip install openviking --upgrade --force-reinstall로 끝나요. 이후 openviking-server init으로 초기 설정을 잡고, openviking-server로 서버를 띄운 뒤 ov status로 상태를 확인해요. 공개 모듈은 코어 서버 openviking, CLI openviking_cli, 프로그램 접근용 sdk, 그리고 확장용 .agents/plugins로 나뉘어 있어요. 벤치마크 수치도 리포에 실려 있어요. LoCoMo 사용자 메모리 태스크는 82% 이상 정확도예요. 지연은 원시 에이전트 대비 59~66% 감소했다고 적혀 있어요. HotpotQA 지식 QA는 top-20 검색에서 91% 정확도에 0.23초예요. Tau2-Bench 멀티턴 태스크는 6~12%포인트 개선이라고 밝혔어요.

가장 가까운 대안은 LangChain·LlamaIndex 같은 오케스트레이션 프레임워크와 mem0·Zep 같은 에이전트 메모리 스토어예요. 다만 그쪽은 메모리·RAG·스킬이 별도 계층으로 얹혀 있고 검색은 대체로 평평해요. OpenViking은 이 셋을 하나의 파일시스템 은유 위에 겹쳐 두고, 리트리벌 궤적도 관측할 수 있게 남겨요. 별 수는 빠르게 붙었지만 첫 릴리스가 이번 여름이라 프로덕션 사례는 아직 리포 안에 축적되는 중이에요. 자기 에이전트에 도입해본다면, 지금 벡터 스토어 하나에 얹혀 있는 문서 코퍼스를 viking:// 디렉터리 얼개로 옮겨보고 같은 질의에서 L0 요약만 로드했을 때 검색 recall이 얼마나 유지되는지부터 계측해보세요.
